# evolantia-signatures

Source of the official HTML email signatures for Evolantia team members, plus a static
preview/copy page. This is not an app: it stores the exact markup people paste into their
Gmail/Outlook signature editor.

## Stack

Plain static HTML/CSS/JS. No build tool, no package manager, no dependencies, no tests.

## Preview

Open `index.html` directly in a browser (no server needed). It renders each signature at
true size (600px) with a "Copiar firma" button that copies the rendered HTML (not source
code) to the clipboard for pasting into a mail client's signature editor.

## Structure

- `index.html` — preview/copy page; one `<section class="card">` per signature, each wrapping
  the signature markup verbatim in a `.sig` div and wired to a copy button via `data-target`.
- `<person>.html` — the canonical signature markup for one person (e.g. `sergio-sorrosal.html`,
  `ricardo-esteruelas.html`). This is what gets copy-pasted into the mail client.
- `<person>-pro.html` — an alternate/card-style variant per person, not linked from
  `index.html`.
- `logo.png`, `icon-mail.png`, `icon-phone.png`, `icon-web.png`, `<person>linkedin.png` —
  image assets referenced by the signatures.

## Hard rules

- Every image in a signature is referenced by its **absolute** raw GitHub URL
  (`https://raw.githubusercontent.com/evolantia/evolantia-signatures/main/<file>.png`), never
  a relative path — mail clients can't resolve local paths, and most block remote images by
  default until the recipient allows them. Renaming or moving an asset breaks every signature
  already pasted into someone's mail client, since those are static copies with no way to
  auto-update. Keep filenames stable. A new asset's URL resolves only after it is merged to `main`, so
  nobody should paste a signature that references it before the merge.
- Signatures are table-based HTML with inline styles, `role="presentation"`, and
  `mso-*` properties — required for Outlook/Gmail rendering. Don't refactor to flex/grid or
  external stylesheets; those don't survive being pasted into a mail client.
- Fixed signature width: 600px (`sergio-sorrosal.html`, `ricardo-esteruelas.html`) or 580px
  (`-pro` variants). Keep new signatures within this range.
- Each signature hardcodes a light-theme lock: `color-scheme:light only` plus a
  `<style>` block with `@media (prefers-color-scheme: dark)` and `[data-ogsb]`/`[data-ogsc]`
  attribute-selector overrides (Outlook.com dark mode). When changing a color or background,
  update it in both the inline style and these override blocks, or dark-mode clients will
  invert it.
- Adding a person: create `<person>.html` following an existing file's structure (same asset
  URL pattern, same light-theme lock, same table layout), then add a matching `<section
  class="card">` block in `index.html` with a new `data-target`/`id` pair.
